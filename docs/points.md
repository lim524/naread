# 일일 포인트 정책

- 한국 시간 자정마다 50P로 갱신. 미사용분 이월 없음.
- 개별 사주·MBTI·태몽: 각각 10P.
- AI 종합: 50P. 종합 입력에서 한 가지 개별 결과만 제공되는 경우 10P.
- 저장 결과 열기·PNG 저장·오늘의 조언: 0P.
- 동일 입력·데이터 버전 종합 결과의 기존 24시간 캐시 재사용: 0P.
- AI 생성/서버 저장 실패·예약 만료: 원래 차감한 날짜에 정확히 한 번 복구. 다음 날 잔액을 추가로 늘리지 않음.

## 운영 적용

001, 002 다음에 `supabase/migrations/003_daily_points.sql`을 적용한다. 과거 `daily_usage_limits.count`는 1회당 10P 사용분으로 변환하며 기존 결과를 삭제하지 않는다. 이후 잔액은 `daily_point_balances`와 `point_ledger`로 관리한다. 이전의 5회 제한 테이블은 과거 기록으로만 남는다.

차감과 결과 저장은 동일 DB 트랜잭션이다. AI 요청은 시작 시 포인트를 예약하고 실패 시 환급한다. 잔액 조회에서도 만료된 예약을 정리한다. 클라이언트가 가격·일자·차감액을 지정하지 못하며 테이블/RPC는 서비스 역할로만 접근한다.

비회원 당일 사용분은 로그인 시 계정에 한 번만 합산한다. 비회원의 남은 일일 지급분을 중복으로 더하지 않는다. 양쪽 사용량 합계가 50을 초과하면 당일 잔액은 0으로 표시한다. 진행 중 요청의 환급 대상도 계정으로 이어지며, 로그아웃으로 기존 비회원 지급분을 다시 받지 않는다.

서버 DB 연결이 없는 미리보기는 서명된 HttpOnly 익명 쿠키와 프로세스 내 지갑을 사용한다. 같은 서버가 실행되는 동안 동시 차감·새로고침·탭 간 사용량을 유지하지만 서버 재시작이나 쿠키 삭제 후의 영구 이용량은 보장하지 않는다. 실제 서비스의 포인트 보존은 Supabase와 003 마이그레이션이 필요하다. 이 미리보기 포인트는 유료 충전 잔액이 아니다.

UI는 `/api/status`의 실제 포인트를 조회한다. 분석 완료·실패, 페이지 이동, 창 복귀, 1분 간격 갱신 때 잔액을 다시 확인한다. 잔액 조회 오류를 새 지급으로 표시하지 않는다.

테스트: `tests/points.test.ts`에서 지급 중복·익일 갱신·각 가격·부족 잔액·동시 요청·실패/만료 환급·로그인 이전·캐시/조언 무료·기존 기록 변환·접근 권한을 검증한다.
